# 🌍 GeoCountry — Panel

Одностраничное веб-приложение (SPA) для определения страны по географическим координатам. Реализовано на **Vue 3** и **Pico.css**, взаимодействует с backend через REST API с помощью **Axios**.

## Возможности

- Регистрация и авторизация пользователей (email + пароль)
- JWT-аутентификация с автоматическим обновлением access-токена по refresh-токену
- Определение страны по широте и долготе
- История запросов с указанием координат, страны и пользователя, который сделал запрос
- Отображение роли пользователя (например, `user`, `admin`)
- Выход из системы с инвалидацией refresh-токена

## Быстрый старт

1. Запустите backend-сервер, реализующий описанный ниже API.
2. При необходимости отредактируйте адрес сервера в `index.html`:
   ```js
   const API_URL = 'http://127.0.0.1:8000';
   ```
   Если backend запускается на другом хосте/порту (например, при доступе с другого устройства в локальной сети), укажите здесь актуальный IP-адрес.
3. Откройте `index.html` в браузере (двойным кликом или через любой локальный HTTP-сервер, например `npx serve .`).

Отдельная установка зависимостей не нужна — файл самодостаточен.

## Ожидаемый API

Frontend обращается к следующим эндпоинтам:

| Метод | Путь                     | Назначение                                   |
|-------|---------------------------|-----------------------------------------------|
| POST  | `/users`                  | Регистрация нового пользователя               |
| POST  | `/users/login`             | Вход (form-urlencoded: `username`, `password`), возвращает `access_token` и `refresh_token` |
| POST  | `/auth/refresh`            | Обновление токена по `refresh_token`          |
| POST  | `/users/logout`            | Выход, инвалидация `refresh_token`             |
| GET   | `/geo/get_country/`        | Определение страны по параметрам `lat`, `lon` |
| GET   | `/geo/get_history`          | Получение истории запросов (с данными о владельце: email, role) |

Access-токен передаётся автоматически в заголовке `Authorization: Bearer <token>` через interceptor Axios.

## Аутентификация

- Токены (`access_token`, `refresh_token`) и данные пользователя (`user_email`, `user_role`) хранятся в `localStorage`.
- При получении `401 Unauthorized` interceptor автоматически пытается обновить `access_token` через `/auth/refresh` и повторяет исходный запрос.
- Если обновление токена не удалось — `localStorage` очищается и страница перезагружается.

## ⚠️ Замечания по безопасности

- Хранение JWT-токенов в `localStorage` уязвимо к XSS-атакам. Для продакшена рекомендуется рассмотреть `httpOnly`-cookies.
- Роль пользователя (`userRole`) на клиенте носит исключительно отображательный характер и не должна использоваться как источник авторизации — все проверки прав доступа должны выполняться на backend.
- Адрес API прописан в коде в открытом виде — для разных окружений (dev/prod) стоит вынести его в конфигурацию.
